# Что проверить на телефоне

Телефон здесь не подключён; установка APK и его работа на Android не проверены.

В текущем `LocalRuntime.kt` используется прямой запуск через musl loader,
а не proot. `HTTPS_PROXY/HTTP_PROXY` направлены в локальный `ConnectProxy`;
он разрешает DNS через Android `InetAddress`. TLS завершает сам opencode,
CONNECT-прокси пересылает зашифрованные байты. AGENTS/части README описывают
старую архитектуру и для диагностики среды не являются источником истины.

1. Открыть настройки клиента, проверить `opencode=1.19.3`, `/doc=loaded`,
   SSE=live, выбранную папку. Отправить `Reply with exactly PHONE_OK`.
   Сначала использовать настроенный AgentRouter, затем Big Pickle.
   Big Pickle уже не ответил и на ПК; одинаковый `retry` не доказывает
   поломку Android/DNS.
2. При зависании сохранить «Copy report»: состояние сервера, retry/error,
   наличие сообщения. Перезапустить приложение, открыть тот же тред:
   если ответ есть после открытия, проблема в отображении/восстановлении,
   если сервер продолжает retry — ожидание происходит в backend.
3. В нативном экране открыть Logs и Copy logs. Смотреть запуск/probe,
   HTTP 204 для prompt_async, события и сетевые диагностические строки.
   Перед передачей отчёта убрать ключи и авторизацию, если они были добавлены
   вручную или попали в сообщения провайдера.
4. Если AgentRouter отвечает на ПК, но тот же провайдер/модель не отвечает
   на телефоне, проверить автоматические дату/время Android, другую сеть
   (Wi-Fi/мобильная), а затем классифицировать конкретную ошибку DNS,
   TCP/CONNECT или TLS по логам. Успешный GET /doc проверяет только loopback
   и не проверяет доступ opencode к HTTPS-провайдеру.

Не отключать проверку сертификатов и не менять защитные заголовки провайдера.
